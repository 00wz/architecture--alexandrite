# Планирование: анализ, идентификация проблем и поиск решений

## Проблемы

- Нет мониторинга — узнаём о деградации со слов клиента.
- Нет централизованных логов — разбор инцидентов идёт со слов клиента и съедает много времени.
- Нет трейсинга — заказ проходит через три сервиса и очередь, и непонятно, где он зависает.
- Дашборд MES со списком заказов медленно грузится, потому что данные тянутся напрямую из БД при каждом запросе.
- Публичный API не защищён от всплесков и от каскадных сбоев при отказе соседних сервисов.

## Инициативы

1. Внедрить мониторинг (метрики приложений, БД, RabbitMQ) и алёрты.
2. Внедрить централизованное логирование.
3. Внедрить распределённый трейсинг.
4. Закешировать дашборд MES со списком заказов.
5. Применить Backpressure на публичном API и Circuit Breaker на интеграциях, чтобы предотвратить каскадные сбои и перегрузку.

## Приоритеты

Сначала наблюдаемость — без неё любые оптимизации делаются вслепую.

1. Мониторинг — быстрее всего отвечает на «где болит».
2. Логирование — даёт ответ «что именно произошло».
3. Кеширование дашборда MES — самая громкая и понятная жалоба, эффект виден сразу.
4. Трейсинг — нужен, чтобы ловить заказы, зависшие в цепочке вызовов.
5. Backpressure + Circuit Breaker — закрывают всплески и каскадные сбои.

## Целевая архитектура через полгода

Над тремя приложениями развёрнута наблюдаемость: метрики стекаются в Prometheus, дашборды в Grafana, логи — в ELK/OpenSearch, трассировки — в Jaeger через OpenTelemetry. Дашборд MES читается из Redis (Cache-Aside), кеш инвалидируется по событию смены статуса заказа. Публичный API ограничен Backpressure, на внешних и межсервисных интеграциях — Circuit Breaker. Команда узнаёт о проблемах по алёртам, а не от пользователей.

## Если бы можно было сделать только три пункта

1. **Мониторинг.** Сейчас вся диагностика — со слов клиентов. Без метрик мы будем дальше тушить пожары вслепую.
2. **Кеширование дашборда MES.** Конкретная и громкая жалоба, эффект виден сразу, реализация локальная.
3. **Трейсинг.** Главные жалобы — «заказ зависает» в распределённой цепочке. Без трасс мы не сможем доказать гипотезу о месте затыка, даже имея метрики и логи.
